# 시스템 아키텍처 문서

## 1. 전체 시스템 구성

본 시스템은 크게 4개의 주요 계층으로 구성되어 있습니다.

- **프론트엔드 (Frontend)**: React 기반 SPA로 구축되어 있으며, 사용자와의 모든 인터랙션을 처리합니다.
- **백엔드 API 서버 (Backend)**: FastAPI 기반으로 구축되어 있으며, 비즈니스 로직 처리와 데이터 접근을 담당합니다.
- **배치/워커 (Batch Worker)**: Celery 기반 비동기 작업 처리기로, 대량 데이터 처리 및 예약 작업을 수행합니다.
- **데이터 저장소 (Data Store)**: PostgreSQL(주 데이터베이스)과 Redis(캐시/세션 저장소)로 구성됩니다.

## 2. 프론트엔드 구성

프론트엔드는 다음과 같은 기술 스택을 사용합니다.

- React 18 + TypeScript
- 상태 관리: Zustand
- API 통신: Axios
- 스타일링: Tailwind CSS
- 빌드 도구: Vite

배포 시 Nginx를 통해 정적 파일을 서빙하며, API 요청은 리버스 프록시를 통해 백엔드로 전달됩니다.

프론트엔드에서 API 서버로의 요청은 `/api/v1/` 경로를 통해 라우팅됩니다.

## 3. 백엔드 API 서버

백엔드는 FastAPI를 기반으로 구축되어 있습니다.

주요 모듈 구성:
- `routes/`: API 엔드포인트 정의
- `services/`: 비즈니스 로직 처리
- `models/`: 데이터베이스 모델 정의 (SQLAlchemy)
- `schemas/`: 요청/응답 데이터 검증 (Pydantic)
- `utils/`: 공통 유틸리티 함수

API 서버는 Uvicorn으로 실행되며, 운영 환경에서는 Gunicorn과 함께 사용됩니다.

환경 변수는 `.env` 파일로 관리하며, 주요 설정값은 다음과 같습니다:
- `DATABASE_URL`: PostgreSQL 연결 문자열
- `REDIS_URL`: Redis 연결 문자열
- `SECRET_KEY`: JWT 토큰 서명에 사용
- `CORS_ORIGINS`: 허용할 프론트엔드 도메인

## 4. 배치/워커 시스템

배치 처리에는 Celery를 사용하며, 브로커로는 Redis를 사용합니다.

주요 배치 작업:
- **일일 리포트 생성**: 매일 오전 2시에 전일 데이터 집계 리포트를 생성합니다.
- **알림 발송**: 사용자 알림(이메일, 푸시)을 비동기로 처리합니다.
- **데이터 정리**: 30일이 경과한 임시 데이터를 정리합니다.
- **외부 API 동기화**: 매시간 외부 시스템과의 데이터를 동기화합니다.

워커 프로세스는 별도의 컨테이너에서 실행되며, Flower를 통해 모니터링할 수 있습니다.

## 5. 데이터 저장소

### PostgreSQL
- 주 데이터베이스로 사용
- 사용자 정보, 주문 데이터, 설정 등 영구 데이터 저장
- Alembic을 통한 마이그레이션 관리
- 읽기 전용 복제본(Read Replica)을 사용하여 조회 성능 향상

### Redis
- 세션 저장소 및 캐시로 사용
- Celery 브로커 역할
- API 응답 캐싱 (TTL: 5분)
- Rate Limiting 구현에 활용

## 6. 서비스 간 통신 흐름

일반적인 요청 처리 흐름:

1. 사용자가 프론트엔드에서 작업을 수행합니다.
2. 프론트엔드가 `/api/v1/` 경로로 API 요청을 보냅니다.
3. Nginx가 요청을 받아 백엔드 API 서버로 프록시합니다.
4. API 서버가 인증을 확인하고 비즈니스 로직을 처리합니다.
5. 필요한 경우 PostgreSQL에서 데이터를 조회하거나 저장합니다.
6. 캐시 가능한 응답은 Redis에 저장하여 다음 요청 시 빠르게 반환합니다.
7. 비동기 작업이 필요한 경우 Celery 태스크를 큐에 추가합니다.
8. 워커가 큐에서 태스크를 꺼내 처리합니다.

## 7. 모니터링 및 로깅

- 애플리케이션 로그: 구조화된 JSON 로그를 stdout으로 출력
- 로그 수집: ELK 스택 (Elasticsearch + Logstash + Kibana)
- 메트릭 수집: Prometheus + Grafana
- 알림: Grafana Alert Rules → Slack 채널 연동
- 에러 추적: Sentry
