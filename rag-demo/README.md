# 📚 문서 기반 RAG 실습 프로젝트

프로젝트 운영 문서를 기반으로 질문에 답변하는 **RAG(Retrieval-Augmented Generation)** 데모 웹앱입니다.

초보자도 RAG의 핵심 흐름을 이해하고 직접 실행해볼 수 있도록 설계되었습니다.

---

## 🤔 RAG란 무엇인가요?

**RAG**는 "Retrieval-Augmented Generation"의 약자로, **검색 기반 증강 생성**을 뜻합니다.

쉽게 말하면:

> AI가 답변을 만들 때, 먼저 관련 문서를 검색한 다음, 그 문서를 근거로 답변을 생성하는 방식입니다.

일반적인 ChatGPT는 학습된 지식만으로 답변합니다. 하지만 RAG를 사용하면:

- **내 문서**를 기반으로 답변할 수 있습니다.
- 근거가 없으면 "모른다"고 답할 수 있습니다.
- 답변의 출처를 보여줄 수 있습니다.

이 프로젝트는 이런 RAG의 핵심 개념을 **가장 간단한 형태**로 실습해볼 수 있게 만들어졌습니다.

---

## 🔄 동작 흐름 (5단계)

이 프로젝트는 아래 5단계로 동작합니다:

### 1단계: 문서 로드
`/docs` 폴더에 있는 `.md`, `.txt` 파일을 읽어옵니다.

### 2단계: 문서 분할 (Chunking)
문서가 길면 AI가 한 번에 처리하기 어렵습니다. 그래서 문서를 적절한 크기의 조각(chunk)으로 나눕니다. 각 chunk에는 출처 파일명과 번호가 메타데이터로 붙습니다.

### 3단계: 임베딩 & 저장
각 chunk를 OpenAI의 임베딩 모델(`text-embedding-3-small`)로 **벡터**(숫자로 이루어진 배열)로 변환합니다. "임베딩"이란 텍스트의 의미를 숫자로 표현하는 것입니다. 비슷한 의미의 텍스트는 비슷한 숫자 배열을 갖게 됩니다. 이 벡터들은 ChromaDB라는 벡터 데이터베이스에 저장됩니다.

### 4단계: 질문 검색 (Retrieval)
사용자가 질문하면, 질문도 같은 방식으로 벡터로 변환합니다. 그런 다음 ChromaDB에서 질문 벡터와 **의미가 가장 비슷한** chunk 3개를 찾아냅니다.

### 5단계: 답변 생성 (Generation)
검색된 3개의 chunk를 OpenAI에 전달하여, **그 근거만을 바탕으로** 답변을 생성합니다. 근거가 부족하면 "찾지 못했다"고 솔직하게 답합니다.

## 🛠️ 기술 스택

| 기술 | 역할 |
|------|------|
| **Python** | 프로그래밍 언어 |
| **Streamlit** | 웹 화면을 쉽게 만들 수 있는 Python 프레임워크 |
| **OpenAI API** | 텍스트를 벡터로 변환하고, 답변을 생성하는 AI 서비스 |
| **text-embedding-3-small** | 텍스트의 의미를 숫자(벡터)로 바꿔주는 모델 |
| **OpenAI Responses API** | 검색된 근거를 바탕으로 답변을 만들어주는 API |
| **ChromaDB** | 벡터를 저장하고 비슷한 내용을 빠르게 찾아주는 데이터베이스 |
| **python-dotenv** | API 키 같은 설정값을 `.env` 파일에서 읽어오는 도구 |

> **참고**: 이 프로젝트는 LangChain을 사용하지 않습니다. RAG의 흐름을 직접 이해할 수 있도록 모든 로직을 직접 구현했습니다.

## 📦 설치 방법

### 사전 준비

- **Python 3.9 이상**이 필요합니다. (`python3 --version`으로 확인)
- **OpenAI API 키**가 필요합니다. [OpenAI 대시보드](https://platform.openai.com/api-keys)에서 발급받을 수 있습니다.

### 1. 저장소 클론

```bash
git clone <저장소 URL>
cd rag-demo
```

> **중요**: 이후 모든 명령어는 반드시 `rag-demo` 폴더 안에서 실행해야 합니다.

### 2. Python 가상환경 생성 (권장)

```bash
python3 -m venv venv
source venv/bin/activate  # macOS/Linux
# 또는
venv\Scripts\activate     # Windows
```

### 3. 패키지 설치

```bash
pip install -r requirements.txt
```

### 4. 환경 변수 설정

```bash
cp .env.example .env
```

`.env` 파일을 열고 OpenAI API 키를 입력합니다:

```
OPENAI_API_KEY=sk-여기에-본인의-API-키를-입력하세요
```

> API 키를 입력하지 않으면 앱 화면에 경고가 표시되고, 인덱싱이나 질문 기능이 동작하지 않습니다.

## 🚀 실행 방법

### 1. Streamlit 앱 실행

`rag-demo` 폴더 안에서 아래 명령어를 실행합니다:

```bash
streamlit run app.py
```

실행하면 브라우저에 자동으로 앱이 열립니다. (기본 주소: http://localhost:8501)

### 2. 문서 인덱싱

앱이 열리면 **왼쪽 사이드바**의 **"Reindex"** 버튼을 클릭합니다.
`/docs` 폴더 안의 문서가 자동으로 읽혀서 검색 가능한 상태로 저장됩니다.

### 3. 질문하기

메인 화면의 입력창에 질문을 입력하거나, 사이드바의 **샘플 질문** 버튼을 클릭합니다.
답변과 함께 근거로 사용된 문서 조각이 함께 표시됩니다.

## 📁 폴더 구조

```
rag-demo/
├── app.py              # Streamlit 웹앱 (메인 UI)
├── ingest.py           # 문서 인덱싱 로직 (로드 → 임베딩 → 저장)
├── rag.py              # 질의응답 로직 (검색 → 답변 생성)
├── utils.py            # 유틸리티 (문서 로딩, chunk 분할)
├── requirements.txt    # Python 패키지 목록
├── .env.example        # 환경 변수 템플릿
├── .gitignore          # Git에서 제외할 파일 목록
├── README.md           # 프로젝트 설명서 (이 문서)
├── GAP_output.md       # GAP 제출용 산출물 문서
└── docs/               # RAG 대상 문서 폴더
    ├── architecture.md     # 시스템 아키텍처 문서
    ├── deploy.txt          # 배포 가이드 문서
    └── troubleshooting.md  # 장애 대응 가이드 문서
```

### 각 파일의 역할

- **`app.py`**: Streamlit으로 만든 웹 UI입니다. 사이드바와 메인 화면을 렌더링합니다.
- **`ingest.py`**: 문서를 읽어서 chunk로 나누고, 임베딩하여 ChromaDB에 저장합니다.
- **`rag.py`**: 사용자 질문을 받아 유사 문서를 검색하고, OpenAI로 답변을 생성합니다.
- **`utils.py`**: 문서 파일 로딩과 텍스트 chunk 분할 기능을 제공합니다.
- **`docs/`**: RAG가 검색할 대상 문서들이 들어 있는 폴더입니다. `.md`, `.txt` 파일만 처리합니다.

## ⚠️ 한계점

이 프로젝트는 학습/실습 목적으로 만들어졌기 때문에 아래와 같은 한계가 있습니다:

1. **소규모 문서만 지원**: 대량의 문서를 처리하기에는 chunk 분할 방식이 단순합니다.
2. **PDF 미지원**: `.md`, `.txt` 파일만 처리합니다.
3. **인증 없음**: 누구나 접근할 수 있는 로컬 데모입니다.
4. **단일 사용자**: 동시에 여러 사용자가 사용하는 것을 고려하지 않았습니다.
5. **단순 chunk 분할**: 문단이나 문장 단위가 아닌 글자 수 기준으로 잘라서, 문장 중간이 잘리는 경우가 있습니다.
6. **임베딩 비용**: 매번 Reindex 시 OpenAI API 호출 비용이 발생합니다.

## 🚀 추후 확장 아이디어

이 프로젝트를 기반으로 아래와 같이 확장할 수 있습니다:

1. **PDF 문서 지원**: `PyPDF2` 등을 사용하여 PDF 파일도 처리
2. **의미 기반 chunk 분할**: 글자 수가 아닌 문단/섹션 단위로 나누어 검색 정확도 향상
3. **대화 히스토리**: 이전 질문을 기억하여 맥락이 이어지는 답변 생성
4. **문서 업로드 UI**: 사이드바에서 직접 문서를 업로드하는 기능
5. **Hybrid Search**: 키워드 검색(단어 일치)과 벡터 검색(의미 유사도)을 함께 사용하여 정확도 향상
6. **답변 피드백**: 사용자가 답변의 품질을 평가할 수 있는 기능
7. **배포**: Streamlit Cloud 또는 Docker를 이용한 배포
8. **사내 문서 연동**: Confluence, Notion 등의 문서를 자동으로 가져오기
